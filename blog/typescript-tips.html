TypeScript Tips for Cleaner Code

Published: January 10, 2026 • 8 min read

TypeScript has evolved far beyond simple type annotations. In 2026, the type system is powerful enough to encode complex business rules, API contracts, and state machines directly into types — catching entire categories of bugs at compile time rather than runtime. The key is knowing which patterns to reach for and when. Over years of building production applications with TypeScript, I've developed a toolkit of patterns that consistently reduce boilerplate and improve safety.

Discriminated unions are my most frequently used pattern. Instead of a status field with a generic string type, define a union of objects with a discriminant property. For example, an API response can be typed as { status: "loading" } | { status: "success"; data: T } | { status: "error"; error: Error }. TypeScript's control flow narrowing handles the rest — you get autocomplete for the data property only when status is "success". Combine this with the satisfies operator to ensure your implementation matches the type without widening. Template literal types are another hidden gem; they let you model URL patterns, event names, or CSS class combinations as precise string types that reject invalid values at compile time.

Generics in TypeScript can go far beyond simple T parameters. Conditional types with infer let you extract return types from functions, unwrap Promise types, or derive element types from arrays. The MapTypes utility pattern — using mapped types with key remapping via as clauses — allows you to transform object types in sophisticated ways. For instance, you can create a type that converts all Date properties to ISO strings for serialization, or one that makes all nullable properties required for form validation. The branded types pattern using intersection types (type UserId = string & { __brand: "UserId" }) prevents accidentally passing a PostId where a UserId is expected, a bug I've seen countless times in untyped codebases.

One pattern that has dramatically improved my code quality is the use of branded types for entity IDs, combined with Zod for runtime validation. When data crosses the network boundary (API response, localStorage, form submission), Zod validates the shape and parses string values into their branded types. The result is a codebase where invalid state is literally unrepresentable. Combined with the exhaustive switch pattern (where the default case asserts never to catch unhandled union members), TypeScript becomes not just a type checker but a code documentation tool that enforces correctness. The initial investment in proper typing pays back exponentially as the project grows, especially during refactoring.
