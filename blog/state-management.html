State Management in React/Next.js

Published: February 5, 2026 • 7 min read

State management in React has evolved significantly. The era of Redux being the default choice for every application is behind us. Modern React development uses a more nuanced approach: server state with TanStack Query, client state with Zustand or Context, URL state with Next.js search params, and form state with React Hook Form. The key insight is that not all state is the same, and using the right tool for each type of state dramatically simplifies your codebase.

Server state — data that lives on the server and needs to be fetched — is best managed by TanStack Query (formerly React Query). It handles caching, background refetching, optimistic updates, and pagination out of the box. For the EAT O'CLOCK dashboard, TanStack Query manages all API data: orders, menu items, reservations, and analytics. The useQuery hook with a properly configured staleTime (30 seconds for order data, 5 minutes for menu items) ensures the UI stays responsive while keeping data reasonably fresh. Mutations use useMutation with onSuccess callbacks that invalidate related queries, triggering automatic refetches. This pattern eliminates the need for a global store for most data — the cache is the source of truth, and the UI reacts to cache changes automatically.

For client-side state that needs to be shared across components, Zustand has become my go-to library. It's minimal (under 1KB), has no boilerplate, and works seamlessly with React server components when used correctly. A typical Zustand store for a shopping cart or UI preferences is a single function call. Zustand's persist middleware with partialize allows selective persistence to localStorage, and the subscribeWithSelector middleware enables granular subscriptions to specific slices of state. For simpler cases, React's built-in Context API with useReducer is sufficient — I use it for theme state and authentication context. The rule of thumb is: if you need it in multiple unrelated components, use Zustand; if it's scoped to a single feature subtree, use Context; if it's component-local, useState is all you need.

URL state is often overlooked but critically important for Next.js applications. Search params, page numbers, filter selections, and sort orders should live in the URL rather than in local state. This makes pages shareable, bookmarkable, and navigable with the browser's back button. Next.js's useSearchParams and the App Router's searchParams prop make URL state a first-class citizen. For form state, React Hook Form with Zod validation handles complex forms with minimal re-renders. The combination of TanStack Query for server state, Zustand for client state, URL state for persistent filters, and React Hook Form for forms creates a state management architecture where each piece has a single responsibility. The result is code that is easier to reason about, test, and debug than any monolithic state solution could provide.
